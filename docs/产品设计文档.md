# 产品设计文档（修订版）

**项目名称：** 生成式AI协作环境下基于学习过程日志的元认知状态推断与自适应干预系统  
**MVP范围：** 本科生开放性写作任务  
**文档版本：** v0.2（已根据审查意见修订）  
**日期：** 2026-09-14

---

## 1. 产品概述

### 1.1 背景

生成式AI（如大语言模型）已广泛进入学习场景，学生可以随时获得问题解答和内容生成。这在提升效率的同时也带来隐患：学生容易跳过计划、不加验证地接受AI输出、缺乏对自身学习过程的反思，即元认知参与度下降。

本系统旨在以轻度侵入的方式，实时感知学生的元认知状态，并在恰当时机提供个性化干预，帮助学生在AI协作中保持主动认知参与。

### 1.2 MVP范围限定

**任务类型：** 仅支持本科生开放性写作任务（如论文引言、读后感、案例分析）  
**不支持：** 数学解题、编程、选择题等其他任务类型

**原因：** 不同任务类型的元认知行为模式差异显著，MVP阶段需要聚焦单一任务类型以确保指标有效性。

### 1.3 目标用户

| 角色 | MVP阶段职责 |
|------|------------|
| 在校学生 | 完成开放性写作任务，与AI协同工作 |
| 研究者（内部） | 收集日志、标注数据、评估干预效果 |

**教师端功能**不在MVP范围内，将在后续版本中加入。

### 1.4 核心价值主张

- **轻度侵入感知**：主要通过自动埋点采集，部分行为需要学生主动标记
- **实时反馈**：状态向量 S(t) 在满足最小样本量后动态更新
- **可解释干预**：每条干预内容附带触发原因和置信度

## 2. 系统架构概述

系统由五层构成，数据自上而下流动：

```
学习任务层          开放性写作（论文、案例分析等）
      ↓
交互数据采集层       对话记录 · Prompt行为 · 编辑轨迹 · 验证行为 · 页面交互
      ↓
元认知状态识别层     Planning · Monitoring · Evaluation → S(t) + 置信度
      ↓
自适应干预决策层     何时干预（状态机） · 干预什么（模板）
      ↓
生成式AI响应层       元认知提示 · 过程支架 · 反思提示
```

**元认知定义（PME）：**

- **Planning（规划）**：学生在使用AI前，对任务目标、输入信息、AI能力边界以及人机任务分工进行提前规划的能力
- **Monitoring（监控）**：学生在AI协作过程中持续监控自身理解、任务进展、AI输出质量以及自身认知偏差的能力
- **Evaluation（评价）**：学生对AI输出质量、人机协作过程以及自身策略效果进行反思和优化的能力

## 3. 功能需求

### 3.1 核心功能

**F1 — 会话管理**
- 创建学习会话，绑定学生ID（脱敏）、任务描述
- 支持会话暂停、恢复、结束
- REST API: `POST /api/sessions/`, `PATCH /api/sessions/{id}/end`

**F2 — 交互数据采集**

采集分为两层：

| 层级 | 事件类型 | 采集方式 | 数据内容 |
|------|---------|---------|---------|
| **自动埋点** | `ai_reply` | 后端推送时自动记录 | AI回复内容、时间戳 |
| **自动埋点** | `focus_switch` | 前端区域焦点切换时自动上报 | 来源区域、目标区域 |
| **自动埋点** | `page_view` | 前端页面访问时自动上报 | 页面名称、停留时长 |
| **用户标记** | `prompt` | 学生在"任务区"主动记录 | Prompt内容、意图 |
| **用户标记** | `edit` | 学生在"任务区"主动记录 | 编辑描述 |
| **用户标记** | `verify` | 学生在"任务区"主动记录 | 验证行为描述 |
| **混合** | `message` | 对话区发送消息时自动采集 | 消息内容 |

**事件数据结构：**
```json
{
  "event_id": "uuid",
  "session_id": "uuid",
  "event_type": "prompt | edit | verify | message | ai_reply | focus_switch | page_view",
  "content": "string",
  "metadata": {
    "source_area": "task | chat | state",
    "sequence_num": 123,
    "client_timestamp": 1234567890
  },
  "server_timestamp": "2026-09-14T12:34:56Z"
}
```

**F3 — 元认知状态识别**

基于滑动窗口（最近N条事件，N=20）提取特征，计算三维状态向量 S(t)。

**状态输出结构：**
```json
{
  "planning": 0.65,
  "monitoring": 0.72,
  "evaluation": 0.58,
  "confidence": {
    "planning": 0.8,
    "monitoring": 0.9,
    "evaluation": 0.6
  },
  "status": {
    "planning": "observed",
    "monitoring": "observed",
    "evaluation": "insufficient_data"
  },
  "feature_coverage": 0.75,
  "computation_version": "v0.1.0",
  "source_events": ["event_id_1", "event_id_2", ...]
}
```

**状态标识：**
- `unknown`：会话初期，尚无足够观察
- `insufficient_data`：该维度观察机会不足（如无AI回复时无法评估Evaluation）
- `observed`：已有足够数据，分数可信

**更新触发条件：**
- 新事件到达 且 距上次计算超过10秒 且 窗口内事件数 ≥ 5

**F4 — 自适应干预**

**干预状态机：**

```
初始状态 → 观察期（前3个事件）→ 
  → 满足触发条件 → 干预冷却期（180秒）→ 
  → 可再次触发
```

**触发条件（优先级从高到低）：**

1. **Planning不足**：`planning < 0.4` 且 `confidence.planning > 0.7` 且 `首次Prompt延迟 < 10秒`
2. **Monitoring不足**：`monitoring < 0.4` 且 `confidence.monitoring > 0.7` 且 `AI阅读时长均值 < 5秒`
3. **Evaluation不足**：`evaluation < 0.4` 且 `confidence.evaluation > 0.7` 且 `粘贴后编辑率 < 0.3`
4. **AI过度依赖**：`AI依赖指数 > 0.5` （跨维度）

**冷却机制：**
- 每次干预后，该类型干预进入180秒冷却期
- 同一会话最多触发6次干预（每维度2次）

**干预类型与模板：**

| 类型 | 适用场景 | 示例内容 |
|------|---------|---------|
| `process_scaffold` | Planning不足 | "在继续之前，请先思考：1) 这个任务的核心目标是什么？2) 你希望AI帮你完成哪部分？" |
| `metacog_prompt` | Monitoring不足 | "建议：仔细阅读AI的回答，思考是否符合你的预期，是否需要进一步澄清？" |
| `reflection_prompt` | Evaluation不足 | "AI的输出只是参考，请结合你自己的理解进行修改和完善。你认为哪些地方需要调整？" |

**F5 — AI对话**
- 学生可直接与AI对话完成写作任务
- 对话历史在会话内保持上下文连贯
- 调用 Anthropic Claude API（Claude 3.5 Sonnet）

### 3.2 辅助功能

**F6 — 状态可视化（研究阶段隐藏）**

在实验验证阶段，雷达图默认对学生隐藏，避免观察者效应。研究者可在后台查看。

- 当前状态雷达图（Planning / Monitoring / Evaluation 三维 + 置信度）
- 历史状态时序折线图，展示会话内状态变化趋势

**F7 — 干预历史**
- 当前会话所有干预记录，含触发原因、置信度、学生是否查看
- HTTP 接口支持研究者查询和导出

## 4. 用户旅程

```
学生打开系统（已通过知情同意）
  → 填写任务描述，创建会话
  → 进入三栏学习界面
      左栏：记录操作行为（发送Prompt/编辑/验证）+ 自动采集页面事件
      中栏：与AI对话，完成写作任务
      右栏：（实验阶段隐藏）实时状态雷达图
  → 状态偏低且置信度足够时，右侧Drawer弹出干预提示
  → 学生阅读提示后继续任务
  → 会话结束后，研究者可导出日志和状态历史
```

## 5. 非功能需求

| 指标 | 目标 | 说明 |
|------|------|------|
| 状态更新延迟 | < 2s（包含LLM调用） | 不在每次事件后立即更新，采用10秒防抖 |
| 干预生成延迟 | < 1s | 使用预定义模板，不调用LLM生成 |
| 并发会话 | 20路 WebSocket | MVP阶段小规模试点 |
| 数据持久化 | PostgreSQL + 每日备份 | 所有日志、状态快照、干预记录落库 |
| 可替换性 | 状态识别模块接口稳定 | 可从规则基线升级为ML模型 |
| 事件可靠性 | 幂等、有序、可重连 | 事件带唯一ID和序号，支持断线重传 |

## 6. 数据模型

```
Session          会话主体
  ├── id (UUID)
  ├── user_id_hash (脱敏学生ID)
  ├── task_description
  ├── status (active | paused | ended)
  ├── created_at, ended_at
  
InteractionLog   操作日志
  ├── event_id (UUID, 唯一)
  ├── session_id
  ├── event_type (prompt | edit | verify | message | ai_reply | focus_switch | page_view)
  ├── content (加密存储，PII脱敏)
  ├── metadata (JSON)
  ├── sequence_num (客户端序号，用于排序和去重)
  ├── client_timestamp
  ├── server_timestamp
  
MetacogState     状态快照
  ├── id (UUID)
  ├── session_id
  ├── planning, monitoring, evaluation (float, 0-1)
  ├── confidence (JSON: {planning, monitoring, evaluation})
  ├── status (JSON: {planning, monitoring, evaluation})
  ├── feature_coverage (float)
  ├── computation_version (string, 例如 "v0.1.0")
  ├── source_event_ids (JSON array)
  ├── features (JSON, 保存12个原始特征值)
  ├── timestamp
  
Intervention     干预记录
  ├── id (UUID)
  ├── session_id
  ├── type (process_scaffold | metacog_prompt | reflection_prompt)
  ├── trigger_reason (string)
  ├── trigger_state (JSON, 触发时的PME分数和置信度)
  ├── content (干预内容)
  ├── viewed_at (学生查看时间，nullable)
  ├── created_at
```

## 7. API 设计摘要

### REST

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/sessions/` | 创建会话 |
| GET | `/api/sessions/{id}` | 获取会话信息 |
| PATCH | `/api/sessions/{id}/end` | 结束会话 |
| POST | `/api/sessions/{id}/logs` | 写入操作日志（批量） |
| GET | `/api/sessions/{id}/states` | 查询状态历史 |
| GET | `/api/sessions/{id}/interventions` | 查询干预历史 |
| PATCH | `/api/interventions/{id}/view` | 标记干预已查看 |

### WebSocket

`ws://host/ws/session/{session_id}`

客户端发送（带序号和时间戳）：
```json
{
  "event_type": "prompt | edit | verify | message | focus_switch | page_view",
  "content": "string",
  "metadata": {...},
  "sequence_num": 123,
  "client_timestamp": 1234567890
}
```

服务端推送类型：

| type | 说明 | payload |
|------|------|---------|
| `ack` | 事件确认 | `{event_id, sequence_num}` |
| `state_update` | 元认知状态向量 | 完整状态对象（含置信度和status） |
| `ai_reply` | AI对话回复 | `{content, timestamp}` |
| `intervention` | 干预内容 | `{type, reason, content, confidence}` |
| `error` | 错误信息 | `{code, message}` |
| `reconnect` | 断线重连指令 | `{last_sequence_num}` |

## 8. 技术选型依据

| 层 | 技术 | 选型原因 |
|----|------|---------|
| 后端框架 | FastAPI | Python 原生异步，WebSocket 支持完善，与 ML 生态无缝对接 |
| 数据库 | PostgreSQL | 结构化日志存储，支持时序查询，JSON字段支持灵活扩展 |
| 缓存 | Redis | 状态向量低延迟读写，会话临时数据（如冷却期）存储 |
| AI 调用 | Anthropic Claude API | 对话质量稳定，延迟可控，支持结构化输出 |
| LLM判断 | Claude 3 Haiku | 低成本、低延迟，适合实时特征提取 |
| 前端框架 | React + TypeScript | 组件化，类型安全，状态管理清晰 |
| 实时通信 | 原生 WebSocket | 轻量，FastAPI 原生支持，支持断线重连 |
| 可视化 | ECharts | 雷达图与时序折线图原生支持，轻量 |
| 加密 | 字段级加密（Fernet） | 日志内容加密存储，密钥通过环境变量注入 |

## 9. 数据隐私与伦理

### 9.1 数据采集与存储

- **知情同意**：学生在首次使用前必须阅读并同意《数据采集知情同意书》
- **脱敏处理**：学生ID采用SHA256哈希，日志内容字段级加密
- **最小化原则**：仅采集与元认知识别直接相关的数据
- **保留期限**：研究结束后6个月内删除所有可识别数据

### 9.2 外部服务数据政策

- **Anthropic API**：
  - 日志内容传输至Claude API进行判断
  - 已确认Anthropic不使用API数据训练模型（参考：[Anthropic数据政策](https://www.anthropic.com/legal/privacy)）
  - 敏感字段（学生ID、真实姓名）在传输前移除

### 9.3 访问权限

| 角色 | 权限 |
|------|------|
| 学生 | 仅查看自己的会话、状态、干预历史 |
| 研究者 | 查看所有会话的聚合数据和匿名化日志 |
| 系统管理员 | 数据库备份、加密密钥管理 |

### 9.4 审计与合规

- 所有数据访问记录审计日志
- 符合《个人信息保护法》和高校研究伦理要求
- 研究方案已提交学校伦理委员会审查（状态：待批准）

## 10. 已知局限与后续方向

### 10.1 MVP阶段局限

- **任务范围窄**：仅支持开放性写作，不支持其他学习任务
- **状态识别基线简单**：采用规则+轻量LLM，精度有限
- **干预策略固定**：使用预定义模板，无个性化生成
- **用户标记依赖**：部分关键事件需要学生主动记录，可能存在漏报

### 10.2 后续方向

**短期（3个月内）：**
- 收集20-30个真实学生会话，标注高/中/低元认知样本
- 训练轻量分类模型（RandomForest或XGBoost）替换规则基线
- 评估干预效果：对比有/无干预组的元认知状态变化和作品质量

**中期（6个月内）：**
- 增加教师仪表盘，支持班级维度的元认知分布分析
- 引入个体基线自适应，避免对低频操作学生过度干预
- 扩展至其他任务类型（案例分析、文献综述）

**长期：**
- 探索生成式干预内容（基于学生当前状态动态生成提示）
- 多模态数据融合（结合文本质量、键盘输入模式）
- 跨学科、跨年级元认知模式对比研究

## 11. 实施计划

### 11.1 阶段划分

| 阶段 | 时间 | 目标 | 交付物 |
|------|------|------|--------|
| **阶段0：技术验证** | 1周 | 搭建系统骨架，模拟数据测试 | 可运行的前后端原型 |
| **阶段1：埋点与基线** | 2周 | 实现12个核心指标计算，规则基线 | 可计算PME分数的系统 |
| **阶段2：小规模试点** | 2周 | 招募5-10名学生，收集真实日志 | 标注数据集（20-30会话） |
| **阶段3：模型训练** | 1周 | 训练分类器，替换规则基线 | 训练好的模型 + 评估报告 |
| **阶段4：效果评估** | 4周 | 对比实验（有/无干预组） | 研究论文初稿 |

### 11.2 成功指标

**技术指标：**
- 状态识别准确率 > 70%（与人工标注对比）
- 状态更新延迟 < 2秒（P95）
- 系统可用性 > 95%

**研究指标：**
- 干预组学生的元认知状态提升幅度 > 对照组
- 干预组学生的作品质量评分 > 对照组（由独立评审员盲评）
- 学生对干预内容的接受度 > 3.5分（5分制）

## 12. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 学生不愿主动标记操作 | 高 | 高 | 简化标记流程，增加自动埋点覆盖 |
| LLM判断延迟过高 | 中 | 中 | 异步处理，使用Haiku模型，缓存结果 |
| 状态识别精度不足 | 高 | 高 | 收集更多标注数据，迭代模型 |
| 伦理审查未通过 | 低 | 高 | 提前沟通，准备替代方案（脱敏程度加强） |
| 学生感到被监控 | 中 | 中 | 知情同意强调研究目的，匿名化保证 |
