# 系统演示场景

## 场景1: 学术写作任务

### 用户信息
- **用户ID**: `demo_user_001`
- **任务类型**: `学术写作`
- **任务描述**: 撰写一篇关于人工智能在教育中应用的综述文章

### 测试步骤

1. **低Planning状态触发**
   ```
   用户输入: "帮我写"
   
   预期行为:
   - Planning状态较低 (< 0.3)
   - 触发元认知提示干预
   - AI建议: "在开始写作前，建议先明确以下几点..."
   ```

2. **高Planning状态**
   ```
   用户输入: "我打算写一篇关于AI教育应用的综述，需要涵盖以下几个方面：
   1. 个性化学习路径
   2. 智能辅导系统
   3. 自动评估与反馈
   请帮我分析第一部分应该如何展开？"
   
   预期行为:
   - Planning状态较高 (> 0.6)
   - 不触发干预
   - 正常对话
   ```

3. **编辑行为触发Monitoring**
   ```
   用户操作: 连续发送 "edit" 事件
   
   预期行为:
   - Monitoring状态上升
   - 状态曲线显示增长
   ```

4. **反思性语言触发Evaluation**
   ```
   用户输入: "我刚才的思路是否合理？这个论证是否充分？还有哪些不足之处？"
   
   预期行为:
   - Evaluation状态上升
   - 包含多个疑问词和反思性词汇
   ```

## 场景2: 问题解决任务

### 用户信息
- **用户ID**: `demo_user_002`
- **任务类型**: `问题解决`
- **任务描述**: 设计一个在线学习平台的推荐算法

### 测试步骤

1. **初始探索阶段（低Planning）**
   ```
   用户输入: "不知道从哪开始"
   
   预期: 触发过程支架干预
   ```

2. **方案设计阶段（高Planning + Monitoring）**
   ```
   用户输入: "我打算使用协同过滤算法，需要考虑用户行为数据和内容特征，
   请帮我评估这个方案的可行性"
   
   预期: Planning和Evaluation都较高
   ```

3. **状态波动（快速切换）**
   ```
   操作序列:
   - 发送长prompt (Planning ↑)
   - 立即发送 "算了，换个思路" (Planning ↓)
   
   预期: 触发波动干预，提示"检测到思路频繁变化"
   ```

## 常见问题排查

### 问题1: WebSocket连接失败
```
症状: 前端显示"WebSocket未连接"，控制台报错

检查项:
1. 后端是否运行 (curl http://localhost:8000/docs)
2. 端口是否被占用 (netstat -ano | findstr 8000)
3. CORS配置是否正确 (检查 .env 中的 CORS_ORIGINS)
4. 防火墙是否拦截

解决方案:
- 确认后端正常启动
- 检查 frontend/.env 中的 VITE_WS_BASE_URL
- 浏览器 Network 标签查看 WebSocket 握手失败原因
```

### 问题2: 状态不更新
```
症状: 发送消息后右侧状态面板无变化

检查项:
1. 后端日志是否显示 [State Update]
2. 前端控制台是否收到 state_update 消息
3. compute_metacog_state() 是否被调用
4. Redis是否正常运行

解决方案:
- 检查 state_recognizer.py 中的计算逻辑
- 确认 WebSocket 推送代码正确执行
- 验证前端 onMessage 处理函数
```

### 问题3: AI不回复
```
症状: 发送消息后没有AI回复

检查项:
1. ANTHROPIC_API_KEY 是否配置正确
2. 后端日志是否显示API调用错误
3. 网络是否能访问 api.anthropic.com
4. API额度是否用尽

解决方案:
- 检查 .env 中的 API Key
- 查看后端详细错误信息
- 测试网络连通性: curl https://api.anthropic.com
- 登录 Anthropic Console 检查用量
```

### 问题4: 干预不触发
```
症状: 即使状态很低也不触发干预

检查项:
1. intervention.py 中的阈值设置
2. 历史状态记录是否足够（需要至少3条）
3. decide_intervention() 返回值
4. WebSocket 推送逻辑

解决方案:
- 临时降低阈值测试（如 0.3 → 0.5）
- 打印 decide_intervention() 的判断过程
- 确认 history 参数传递正确
```

### 向导师/评审展示时的流程

1. **系统启动演示（2分钟）**
   - 展示启动后端、前端的命令
   - 访问 http://localhost:8000/docs 展示API文档
   - 访问 http://localhost:5173 展示前端界面

2. **核心功能演示（5分钟）**
   - 创建会话（学术写作任务）

   - 发送高Planning消息 → 正常对话

   - 展示状态曲线 → 说明实时更新

3. **技术架构说明（3分钟）**
   - 打开 README.md，展示架构图
   - 说明数据流：前端 → WebSocket → 状态识别 → 干预决策 → AI生成

   - 提到可训练机器学习模型
   - 提到可收集真实数据进行实验验证
